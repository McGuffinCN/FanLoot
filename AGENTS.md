# FanLoot Agent Guide

Quick onboarding for coding agents working in this repo.

## What this is

FanLoot is a **batch downloader** for already-unlocked creator posts on:

- Fantia
- pixivFANBOX
- Patreon
- Pawchive

Primary deliverable is a single isomorphic script:

- `fanloot.user.js` runs as a Tampermonkey userscript
- the same file is copied into `dist-extension/content.js` for a Chrome/Edge MV3 extension

Current version is read from the userscript header `@version`.

## Architecture

### Dual runtime

`fanloot.user.js` detects runtime at boot:

- Tampermonkey / Greasemonkey: use `GM_download`, `GM_xmlhttpRequest`, `GM_*Value`, `GM_registerMenuCommand`
- Chrome/Edge extension: `IS_EXT === true` when `chrome.runtime.id` exists and `GM_download` is absent

Extension adapters in the same file:

- storage: `chrome.storage.local` hydrated into `extStorageCache`
- cross-origin fetch: background message `FANLOOT_XHR`
- downloads: background message `FANLOOT_DOWNLOAD` + progress/done events
- open panel: `FANLOOT_OPEN_PANEL` from action click

Background worker / referer rules / store locales are generated by `build_extension.py`.

### High-level flow

1. Inject floating launcher + shadow-DOM panel into supported pages.
2. Parse target URL for current site only. **No cross-site crawling.**
3. Crawl post list / single post.
4. Extract media/text/cloud-link items into `state.posts`.
5. Apply filters into `state.filtered`.
6. Download with concurrency, pause/stop/retry, skip-history.

Important state:

- `settings` persisted under `fantiaDL.settings.v1`
- download history under `fantiaDL.history.v1`
- `state.posts` / `state.order` / `state.filtered` / `state.dl`

### Code sections in `fanloot.user.js`

Approximate map:

- header metadata: userscript `@match` / `@grant` / `@connect`
- i18n: `detectUiLang()`, `I18N`, `t()`
- site helpers: `detectSite()`, `siteOrigin()`, theme
- naming: `buildPath()`, `sanitizeSegment()`, template vars
- parsers: Fantia / Fanbox / Patreon / Pawchive extractors
- runtime state + request helpers: `requestFantia/Fanbox/Patreon/Pawchive`
- crawl / download / UI: `crawl()`, `startDownload()`, `mountUI()`, `init()`

UI is built with `buildHtml()` + Shadow DOM host `#fanloot-downloader`.

## Build / package

```powershell
python build_extension.py
```

Outputs:

- `dist-extension/` loadable via Chrome/Edge developer mode
- `fanloot-extension.zip` for store upload

Build also:

- copies `fanloot.user.js` → `dist-extension/content.js`
- writes `manifest.json`, `background.js`, `rules.json`
- writes `_locales/zh_CN` + `_locales/en`
- generates icons from `icon.png` / `icon128.png` when present

Store description length matters: English `extensionDescription` must stay ≤ 190 chars.

## i18n rules

- UI language follows **primary** browser/extension language.
- `zh*` → Chinese, otherwise English.
- Prefer `chrome.i18n.getUILanguage()` in extension, then `navigator.language` / first preferred language.
- Do **not** scan the entire `navigator.languages` list for any Chinese entry; bilingual users would get stuck on Chinese.
- Panel/runtime strings go through `t('key', vars)`.
- Extension store listing strings live in `build_extension.py` `LOCALES` / `_locales/*/messages.json`.

## Site constraints agents must preserve

- Operate only on the current page site (`PAGE_SITE`). Reject cross-site targets.
- Only unlocked content is downloadable; locked/stream-only items are counted separately.
- Dates are JST-based for filters/formatting.
- Fantia / Fanbox / Patreon download URLs often expire; re-crawl is expected after failures.
- Pawchive has no membership-plan model like the others.
- Patreon supports collections; Fanbox/Fantia mainly plan filters.
- Cloud-link extraction / iframely resolve exists for Fanbox + Pawchive cards.

## Edit conventions

1. Prefer editing `fanloot.user.js` as the single source of truth.
2. After userscript changes that affect the extension, run `python build_extension.py`.
3. Keep Tampermonkey compatibility. Do not remove `GM_*` paths when adding extension adapters.
4. Keep Shadow DOM UI self-contained; avoid depending on host-page CSS.
5. When adding UI text, add both `zh` and `en` keys in `I18N`.
6. After bug fixes / product changes, bump userscript `@version` (default **patch**: `x.y.Z+1`), then `python build_extension.py` so `manifest.json` / `content.js` match. Use minor/major only when the user asks.
7. Do **not** auto-push or auto-create GitHub Releases. After bump/rebuild, ask whether to commit, push to `origin`, and/or publish Release `vX.Y.Z` (assets: `fanloot-extension.zip` + `fanloot.user.js`).
8. Do not broaden host permissions casually. Store review cares about `<all_urls>`-style access.
9. Do not commit local scratch, PSD sources, or temporary `_tmp_*.py` helpers unless asked.

## Common tasks

### Add / fix a site parser

Start from:

- target parsing: `parseTarget()` / site-specific parsers
- list crawl: `listPosts()` path used by `crawl()`
- post extract: `extractFantiaPost` / `extractFanboxPost` / `extractPatreonPost` / `extractPawchivePost`
- normalize through `extractPost()` + `filterEntries()`

Use `site-sample/` or `local/` HTML/JSON captures when available for offline inspection.

### Change download behavior

- queue/concurrency/retry: `startDownload()`, `pump()`, `launch()`
- userscript path: `GM_download`
- extension path: `startNativeDownload()` + generated `background.js`

### Change UI

- structure/copy: `buildHtml()` and render helpers near the UI section
- theme accents: `siteTheme()` / `applyTheme()`

## Verification checklist

- Tampermonkey: install/update `fanloot.user.js`, hard-refresh a supported page, open panel.
- Extension: load `dist-extension` unpacked, click action icon, confirm panel opens.
- Language: primary browser language English → English UI; Chinese → Chinese UI.
- Smoke each touched site: Fantia / Fanbox / Patreon / Pawchive on creator page and one post page.
- Confirm no cross-site target leakage when switching tabs/sites.
- After packaging, confirm `dist-extension/manifest.json` version matches `@version`.

## Non-goals

- Not a piracy tool. It organizes content the signed-in account can already access.
- Not a generic multi-site scraper framework. Site adapters are intentionally concrete.
- Not a Node app. There is no runtime package.json workflow for the userscript itself.
